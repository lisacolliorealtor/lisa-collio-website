## Mechanical checks now in place

Recorded so future sessions know what is already enforced and don't rebuild it.

| Check | What it catches |
| --- | --- |
| `npm run check:images` | Every slug classified overlay-or-clean; in-scope files carry a band, out-of-scope files don't; every referenced file exists; section images recorded in `SECTION_JOBS` |
| `audit.js` check 14 | EN/ES image-count parity, using `content/hreflang-pairs.json`; baselined gaps can only shrink |
| `audit.js` check 15 | Fails the build if any page references one of the four rejected assets, in any variant |
| `audit.js` check 16 | FAQ image ↔ question-link agreement — catches an image attached to the wrong question |
| `audit.js` check 17 | Fair Housing banned terms in **alt attributes**, EN + ES, from `content/source/fair-housing-terms.txt`. Deliberately scoped to alt only — body copy is not gated |
| `scripts/fair-housing-proximity-probe.js` | Body-copy banned terms, flagged only within 4 words of a place word (neighborhood/area/street/residential/community). 94% suppression, zero false positives and zero false negatives on the known set. **Committed but wired into no build step** — run manually as content changes |
| Proposed, not built | Meta and og/twitter descriptions scanned for identity rules and banned terms; hero copy scanned for banned terms |

**Build-record additions (why they matter):** `SECTION_JOBS` records source photo, focal point, crop, and the original's git blob SHA for every section image. `OVERLAY_JOBS` does the same for Template A featured images — added 29 July 2026 after a regenerated image had to be reverse-engineered by hash-matching, because nothing recorded which photo or colour variant built it. `generate_header_thumb()` brought the 800×420 card thumbnail into the script; it had been produced out of band, which is precisely why it couldn't be reproduced. **Every generated artifact needs a build record, or it becomes unreproducible the moment it needs changing.**
